# MCP Servers: Zero to Hero

A practical book about building Model Context Protocol servers that survive contact with
production — written against protocol revision **`2026-07-28`**, with a running project you
can check out at any chapter.

**Read it:** <https://irfan-ai-technologies.github.io/mcp-server-tutorial/> — or open
`book/index.html` from a clone. Chapters are plain HTML with no build step required to read
them.

> **Status: in progress.** Parts 0 to 2 are drafted and Part 3 is under way — chapters 1
> to 14, with `ledger` stateless over HTTP behind 61 tests, a measured token budget,
> signed handles in place of the sessions the protocol removed, and an enforced
> idempotency key on the one tool that writes. Chapters are published as they are written and
> each carries its own status. See the [contents page](book/index.html) for what is drafted, reviewed, or
> still planned, and [`PLAN.md`](PLAN.md) for the full outline and where the work is going.

## What this is

Most MCP material stops at "here is a server with a tool on it". That part takes an
afternoon. This book is about everything after: what your tool surface costs in someone
else's context window, how state works now that the protocol has none, what breaks under
concurrent agents, and how to keep a large capability surface usable inside a finite window.

The organising idea: **an MCP server is a prompt.** Every tool name, description, schema and
result is text loaded into a context window you don't control and don't pay for. Most of the
scale problems in this book are that one fact wearing different clothes.

**Who it's for:** engineers and architects who write Python, have shipped something with
async and HTTP in it, and have opinions about retries. Part 1 gets everyone to a working,
tested server in five chapters and then stops.

**What it isn't:** an SDK tour. The reference docs are good and are linked, not restated.

## A note on timing

Revision `2026-07-28` is the largest break since MCP launched. Protocol-level sessions and
the `initialize` handshake are gone; servers that need cross-call state mint explicit
handles. Server-initiated requests are replaced by the Multi Round-Trip Request pattern.
Roots, Sampling and Logging are deprecated. Stream resumability is removed.

A large share of the MCP writing currently online describes a protocol that no longer
exists. Everything here is written against the current one, and every protocol claim links
to the specification.

## The spine project

Chapters build one server, `ledger` — an MCP server over a media rights catalogue, with
enough real structure to produce the problems honestly: result sets large enough to blow a
context window, a contract corpus deep enough to need progressive disclosure, a job slow
enough to need the tasks extension, and several tenants.

Each chapter that changes it names a tag:

```bash
git checkout ch12-state-handles   # ledger exactly as it stands at the end of chapter 12
```

Part 1's five tags all point at the same commit: those chapters were written against a
server that was built as a unit. From Part 2 onwards each tag marks a distinct state.

All data is synthetic and generated by a script in `data/`. No real agreements, parties or
client material appear anywhere in this repository.

## Working on the book

The builder needs only [uv](https://docs.astral.sh/uv/); dependencies are pinned inline in
the script, so highlighting is byte-for-byte reproducible.

```bash
uv run scripts/build.py new ch12-life-after-sessions   # scaffold a chapter from the template
uv run scripts/build.py build                          # regenerate nav, headers, includes
uv run scripts/build.py site                           # assemble book/_site for publishing
uv run scripts/build.py check                          # what CI runs
```

Chapters are self-contained HTML documents. The builder rewrites only the regions marked
`BEGIN:` / `END:` — title, sidebar, chapter header, pager — and leaves everything between
`BEGIN:body` and `END:body` alone. Code is never pasted; it is pulled from real files:

```html
<!-- include: code/ledger/src/ledger/handles.py lang=python region=mint -->
<!-- endinclude -->
```

`region=mint` refers to `region: mint` / `endregion: mint` markers in the source file, so a
snippet survives edits above it. CI fails if a chapter's generated regions are stale, if an
include target is missing, or if an internal link is dead.

Keep code lines under about 78 characters — a chapter column is narrower than an editor.
